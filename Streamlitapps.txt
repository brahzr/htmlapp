## 4. Deck schema (use exactly; extend only via schema_version bump)
```python
from typing import Annotated, Literal, Union
from uuid import uuid4
from pydantic import BaseModel, Field

def _id() -> str:
    return uuid4().hex[:8]

class _Block(BaseModel):
    id: str = Field(default_factory=_id)

class TextBlock(_Block):
    type: Literal["text"] = "text"
    text: str

class BulletsBlock(_Block):
    type: Literal["bullets"] = "bullets"
    items: list[str]
    fragments: bool = False          # reveal items one by one

class ImageBlock(_Block):
    type: Literal["image"] = "image"
    src: str                          # data URI
    alt: str = ""
    caption: str = ""

class TableBlock(_Block):
    type: Literal["table"] = "table"
    headers: list[str]
    rows: list[list[str]]

class ChartBlock(_Block):
    type: Literal["chart"] = "chart"
    chart_type: Literal["bar", "line", "pie"]
    labels: list[str]
    series: dict[str, list[float]]
    source_table_id: str | None = None

class CodeBlock(_Block):
    type: Literal["code"] = "code"
    language: str = "python"
    code: str

class QuoteBlock(_Block):
    type: Literal["quote"] = "quote"
    text: str
    source: str = ""

class QuizBlock(_Block):
    type: Literal["quiz"] = "quiz"
    question: str
    options: list[str]
    answer_index: int

Block = Annotated[
    Union[TextBlock, BulletsBlock, ImageBlock, TableBlock, ChartBlock,
          CodeBlock, QuoteBlock, QuizBlock],
    Field(discriminator="type"),
]

class Slide(BaseModel):
    id: str = Field(default_factory=_id)
    title: str = ""
    layout: Literal["title", "section", "title_bullets",
                    "two_column", "image_focus"] = "title_bullets"
    blocks: list[Block] = []
    notes: str = ""
    source_ref: str | None = None     # e.g. "page 3" / "heading 2.1"

class Theme(BaseModel):
    name: str = "clean"
    font_heading: str = "Inter"
    font_body: str = "Inter"
    primary_color: str = "#1F4E79"
    background: str = "#FFFFFF"
    direction: Literal["ltr", "rtl"] = "ltr"

class Deck(BaseModel):
    schema_version: Literal["1.0"] = "1.0"
    title: str
    language: str = "en"
    theme: Theme = Theme()
    transition: Literal["none", "fade", "slide", "convex"] = "slide"
    slides: list[Slide] = []
```

## 5. Edit operations (UI and AI both use these; AI NEVER returns a full deck)
```python
class EditOp(BaseModel):
    op: Literal["update_title", "rewrite_block", "add_block", "delete_block",
                "split_slide", "merge_slides", "move_slide", "delete_slide",
                "change_layout", "set_notes", "table_to_chart", "add_quiz"]
    slide_id: str
    target_id: str | None = None      # block id or second slide id
    payload: dict = {}                # define a typed payload model per op
    rationale: str = ""               # shown to the user next to the suggestion

class Suggestion(BaseModel):
    summary: str
    ops: list[EditOp]
```
Each op = a pure function `apply(deck, op) -> Deck` that never mutates
its input. History = a list of Deck snapshots in session_state (max 50).

## 7. Parsing rules & hard cases
- Segmentation: new slide at H1/H2 (or detected heading font size);
  split when a slide exceeds 6 bullets or ~60 words.
- Multi-column PDFs: detect columns from word x-positions; read left→right.
- Footnotes/page numbers/headers: strip repeated text; footnotes → notes.
- Equations & complex figures: keep as cropped images.
- Scanned PDFs (no text layer): detect and warn; OCR is Phase 2.
- HTML: sanitize with nh3; drop scripts, iframes, event handlers.
- Every slide keeps source_ref so users can trace content back.

```python
from typing import Literal
from pydantic import BaseModel, Field
from uuid import uuid4

def _id() -> str:
    return uuid4().hex[:8]

Task = Literal["regression", "binary", "multiclass", "timeseries"]

class Step(BaseModel):
    id: str = Field(default_factory=_id)
    kind: Literal["drop_duplicates", "drop_rows", "drop_columns", "cast_type",
                  "impute", "outlier_treatment", "transform"]
    columns: list[str] = []
    params: dict = {}
    # pre_split: deterministic row/column ops applied once to the full data
    # in_pipeline: learned ops (impute, cap, scale) refit on TRAIN folds only
    stage: Literal["pre_split", "in_pipeline"]

class PreprocessConfig(BaseModel):
    scaler: Literal["none", "standard", "minmax", "robust", "maxabs",
                    "quantile", "power_yeojohnson", "log1p"] = "standard"
    encoder: Literal["onehot", "ordinal", "target"] = "onehot"
    test_size: float = 0.2
    cv: Literal["kfold", "stratified", "timeseries"] = "kfold"
    n_splits: int = 5
    random_state: int = 42

class ModelRun(BaseModel):
    id: str = Field(default_factory=_id)
    family: Literal["classic", "ml", "dl"]
    name: str
    params: dict = {}
    metrics: dict[str, float] = {}
    diagnostics: dict = {}            # classic models only
    artifact_path: str | None = None

class Widget(BaseModel):
    id: str = Field(default_factory=_id)
    kind: Literal["kpi", "chart", "table", "metrics", "importance",
                  "predict_form", "text"]
    config: dict = {}
    position: tuple[int, int] = (0, 0)   # grid row, col
    width: int = 6                        # of 12 columns

class DashboardSpec(BaseModel):
    title: str = "Dashboard"
    filters: list[str] = []               # columns used as live filters
    widgets: list[Widget] = []

class ProjectState(BaseModel):
    schema_version: Literal["1.0"] = "1.0"
    dataset_name: str
    target: str | None = None
    features: list[str] = []
    task: Task | None = None
    datetime_col: str | None = None
    steps: list[Step] = []
    preprocess: PreprocessConfig = PreprocessConfig()
    runs: list[ModelRun] = []
    dashboard: DashboardSpec = DashboardSpec()
```

## 5. Page specifications

### 5.1 Data
- Upload, preview, dtype inference with user override, memory usage
- Select target + features (default: all except target and ID-like columns)
- Auto-detect task from target (user can override); detect datetime column
- Pages after this one are locked until a target is chosen

### 5.2 Cleaning (each action: preview before/after → Apply → logged → undo)
Outliers
- Detection methods: IQR/boxplot (k adjustable, default 1.5), z-score,
  modified z-score (MAD), Isolation Forest (multivariate)
- Per-column boxplot with outliers highlighted; count and % per column
- Treatments: remove rows, cap/winsorize at bounds, replace with median,
  log/Yeo-Johnson transform, flag column, keep
Missing values
- Table of count/% per column + missingness matrix plot
- Treatments: drop rows, drop columns above threshold %, mean, median, mode,
  constant, forward/back fill (time series), KNN imputer, iterative imputer
- Rule: if a column has outliers, recommend median (not mean) and explain why
Duplicates
- Exact duplicates and duplicates on a chosen column subset
- Treatments: keep first, keep last, drop all
Data quality score (0–100) shown before and after cleaning.

### 5.3 EDA
- Summary statistics: count, mean, std, min, quartiles, max, skewness,
  kurtosis, missing %, unique; grouped by a chosen categorical column
- Distributions: histogram + KDE, boxplot, violin, QQ-plot
- Relationships: scatter vs target, pairplot (sampled), grouped bar charts
- Correlation (heatmap for each, with clustered ordering option):
  Pearson, Spearman, Kendall (num–num); point-biserial (binary–num);
  Cramér's V (cat–cat); correlation ratio η (cat–num); mutual information
  with target; partial correlation
- Trees & hierarchy: feature dendrogram (distance = 1 − |corr|),
  observation dendrogram (sampled), shallow decision tree explaining the
  target (max_depth 3–4), treemap of categorical composition
- Time series (if datetime_col): line plot, rolling mean, seasonal
  decomposition, ACF/PACF
- Auto-generated plain-language insights (e.g. "x1 and x2 correlate 0.92:
  multicollinearity risk")

### 5.4 Modelling
Common preprocessing panel: scaler, encoder, split, CV (from PreprocessConfig).
All learned steps go inside a scikit-learn Pipeline fit on train only.

Classic (statsmodels)
- Estimators: OLS, WLS, GLS, Robust (RLM), Quantile regression, 2SLS/IV,
  Logit, Probit, Multinomial Logit, Poisson, Negative Binomial,
  ARIMA/SARIMAX (time series)
- Covariance options: nonrobust, HC0–HC3, HAC (Newey-West)
- Output in EViews-style table: coefficient, std error, t/z, p-value,
  R², adj. R², F-stat, AIC, BIC, log-likelihood, Durbin-Watson
- Diagnostics (each shows H0, statistic, p-value, verdict at chosen α,
  and a plain-language recommendation):
  Normality: Jarque-Bera, residual histogram, QQ-plot
  Serial correlation: Durbin-Watson, Breusch-Godfrey LM, Ljung-Box Q,
  residual correlogram
  Heteroskedasticity: Breusch-Pagan, White, ARCH LM
  Specification: Ramsey RESET
  Multicollinearity: VIF, condition number
  Stability: Chow breakpoint (user picks break), CUSUM
  Coefficient tests: Wald restrictions (user-entered, e.g. "x1 = x2")
  Stationarity (time series): ADF, KPSS
  Example recommendation: "Heteroskedasticity detected → refit with HC3"

Machine learning (scikit-learn, XGBoost, LightGBM)

- Optimizer: SGD (+momentum), Adam, AdamW, RMSprop, Adagrad

```python
    open_access: bool | None = None
    methods: list[str] = []           # extracted from abstract
    datasets: list[str] = []          # extracted from abstract
    source: str                       # "openalex", "semantic_scholar", ...
    retrieved_on: date

class Author(BaseModel):
    name: str
    openalex_id: str | None = None
    orcid: str | None = None
    affiliation: str | None = None
    country: str | None = None
    works_in_topic: int
    total_citations: int | None = None
    h_index: int | None = None
    top_paper_ids: list[str] = []     # evidence IDs
    profile_url: HttpUrl | None = None

class Journal(BaseModel):
    name: str
    publisher: str | None = None
    issn: list[str] = []
    in_doaj: bool | None = None
    open_access: bool | None = None
    apc_usd: float | None = None
    mean_citedness_2y: float | None = None   # NOT Impact Factor; label it
    topic_papers: int                         # topic papers it published
    example_paper_ids: list[str] = []
    fit_score: float                          # 0–1, explained in UI
    scope_url: HttpUrl | None = None

class SpecialIssue(BaseModel):
    title: str
    journal: str
    deadline: date | None = None
    guest_editors: list[str] = []
    url: HttpUrl
    retrieved_on: date
    status: Literal["open", "closed", "unknown"]
    origin: Origin = "verify"

class Dataset(BaseModel):
    name: str
    source: str                       # zenodo, huggingface, openml, ...
    url: HttpUrl
    license: str | None = None
    size: str | None = None
    used_in_paper_ids: list[str] = []

class Claim(BaseModel):
    text: str
    evidence_ids: list[str]           # must be non-empty and valid

class ResearchBrief(BaseModel):
    schema_version: Literal["1.0"] = "1.0"
    query: str
    keywords: list[str]
    overview: list[Claim]
    titles: list[str]                 # origin = suggested
    problem_statement: list[Claim]
    gaps: list[Claim]
    research_questions: list[str]
    hypotheses: list[str]
    papers: list[Paper]
    authors: list[Author]
    methods: list[dict]               # method, frequency, paper_ids, when_to_use, python_lib
    datasets: list[Dataset]
    journals: list[Journal]
    special_issues: list[SpecialIssue]
    next_steps: list[str]
```

## 6. Research Brief sections (output for every query)
1. Topic overview: 4–6 cited sentences on the state of the field
2. Proposed titles: 5 options (empirical, methodological, comparative,
   applied, review), labelled Suggested
3. Research problem: problem statement, 3–5 gaps derived from limitations
   and future-work statements in retrieved papers, research questions and
   testable hypotheses; each gap cited
4. Recent literature table: title, authors, year, venue, citations,
   method, one-line key finding, open access, DOI link; sortable,
   filterable by year/citations/OA
5. Key authors table: name, affiliation, country, ORCID, topic works,
   total citations, h-index, top paper, profile link
6. Methods & models table: method, how often used in retrieved papers,
   example papers, when to use, Python library
7. Datasets table: name, source, license, size, papers using it, link
8. Target journals table: name, publisher, ISSN, DOAJ, OA/APC,
   2-year mean citedness (labelled "not Impact Factor"), topic papers
   published, fit score with explanation, scope link
9. Special issues table: title, journal, deadline, guest editors, status,
   retrieved date, link; past deadlines hidden by default
10. Next steps: reading order, a suggested first experiment, journals to check

## 7. Retrieval & ranking
- Query expansion: LLM proposes synonyms/related terms; show them as
  editable chips before searching (works without AI using the raw query)
- Sources: OpenAlex + Semantic Scholar + Crossref (core), arXiv and PubMed
  (discipline-dependent), CORE (open-access full text)
- Ranking score = relevance (hybrid BM25 + embedding similarity)
  + recency weight + log(citations), weights configurable
- Separate "Seminal works" (highly cited, any year) from "Recent works"
- Author ranking: topic works × citation impact within the topic,
  disambiguated by OpenAlex ID / ORCID
- Journal fit: share of topic papers published + embedding similarity
  between topic and journal scope
- Datasets: Zenodo, DataCite, Hugging Face Hub, OpenML + dataset mentions
  extracted from retrieved abstracts
- Special issues: fetch publisher call-for-papers pages (e.g. MDPI,
  Springer, Elsevier, Frontiers, IEEE) only where robots.txt and terms
  allow; cache 24 h; parse deadlines; support a manually curated list
- Verify current auth, rate limits and terms for every API at build time;
  use polite headers (mailto) and exponential backoff

## 8. Chat behaviour
- After the Brief, users can ask follow-ups ("compare method A vs B",
  "only papers from Africa", "papers since 2024", "explain gap 2")
- Follow-ups reuse the evidence store and retrieve more when needed
- Consensus mode for yes/no research questions: classify each relevant
  paper as supports / contradicts / mixed / unclear, show a distribution
  bar with counts and the cited papers behind each class
- Answer in the user's query language; keep titles in original language
- Students may not use the app to write full papers: it helps with
  framing, discovery and planning, and says so in the UI

## 9. Exports & persistence
- Export Brief as Markdown, DOCX and PDF; references as BibTeX, RIS, CSV
- Save sessions (query, evidence store, brief) locally in SQLite
- Saved searches with "what's new since last time" refresh

## 10. Quality evaluation (measured, not guessed)
- Citation validity: 100% of displayed DOIs resolve; 0 fabricated items on
  a 30-query adversarial test set (obscure or non-existent topics included)
- Grounding: 100% of Claims carry valid evidence IDs (validator test)
- Recall: on a gold set of 10 topics with 5 known key papers each
  (provided by me), ≥ 80% appear in the top 30 results
- Author disambiguation: spot-check 20 authors; report error rate
- Latency: report p50/p95 time-to-brief; target p50 < 60 s
- Special issues: report precision of "open" status on 20 samples

## 11. Engineering rules
- Package layout: core/, sources/<one module per API>/, retrieval/,
  ranking/, synthesis/, validation/, scrapers/, export/, ui/
- Each source implements one interface: search(query, filters) -> list[Paper]
- Async parallel calls with timeouts; a failing source degrades gracefully
  and is reported in the UI
- No file > 300 lines; no TODOs or placeholders in delivered code
- Pin versions; list each dependency's license and each source's terms
- API keys in sidebar or env vars only; never logged
- If unsure of an API endpoint or field, say so; never invent one
- Explain any trade-off in 1–2 lines

## 12. Working protocol (strict)
For EACH stage: (1) restate the stage goal in ≤ 5 bullets, (2) list
assumptions, (3) ask ≤ 5 questions, then STOP and wait for my answers.
After approval: deliver folder tree → code file by file → tests →
test results and metrics from section 10 → known limitations.
